## 一、设计理念

```
个人线（太阁立志传式）：
  行事正义或邪恶 → 影响 NPC 态度与势力关系
  自由修炼突破 → 修为与宗门身份解耦，各自独立推进
  行走江湖 → 探索各门派城市，触发随机事件

势力线（信长之野望式）：
  从外门弟子 → 内门 → 真传 → 长老 → 掌门（贡献值驱动）
  势力倾向（正道/中立/邪道/混乱）→ 驱动 NPC 和势力间外交行为
  NPC 个性受势力文化影响 → 友好或敌对行为非纯随机

⚠️ 沙盒 = 地基：沙盒模式是整个游戏的底层框架，不是可切换的"模式"。
剧情通过直接修改 PlayerState 字段（类似作弊指令）来推进，两者共享同一套系统。
新开发者应始终以"打磨沙盒底层"为第一优先级。
```

## 二、与现有系统的关系

### 2.1 修为与宗门身份解耦（已实装）

| 维度 | 主线模式 | 沙盒模式 |
|------|---------|---------|
| 修为突破 | 剧情解锁 `realmBreakUnlocked` → 玩家点击突破 | 同上，或通过突破丹替代剧情解锁 |
| 宗门身份 | 剧情设置 `discipleRank` | 贡献值 + 晋升试炼 → 平行晋升路径 |
| 两者关系 | 完全解耦，互不影响 | 同左 |

### 2.2 核心规则

- 沙盒路径才是"真实的成长路径"：做日常 → 攒贡献 → 完成试炼 → 晋升
- 剧情晋升和沙盒晋升写入**同一个 `discipleRank` 字段**
- 如果先通过沙盒升到内门，主线推进到对应节点时检测到已是内门则自动跳过
- 切回主线时，修为、身份、NPC 状态、好感度全部保留

| 维度 | 沙盒路径（真实成长） | 剧情路径（作弊直达） |
|------|---------------------|---------------------|
| 修为突破 | 修炼 + 突破丹 | 剧情解锁 `realmBreakUnlocked` |
| 宗门身份 | 贡献值 + 晋升试炼 | 剧情直接设置 `discipleRank` |
| 技能获取 | 宗门习武 + 偷师 + 拜师 | 剧情 VN 授予 |
| 核心循环 | 做任务 → 攒贡献 → 晋升 → 更高阶任务 | 推剧情 → 得数值 → 推下一段剧情 |

### P8: NPC 三角金字塔 + 天赋池 + 天骄（⭐⭐⭐⭐ 高优先级）

**当前问题**：NPC 生成使用旧的 6 门派简单随机规则，无天赋系统，NPC 之间除了名字无差异。

**目标**：
1. 按宗门层级三角金字塔生成 NPC（数量与宗门地位挂钩）
2. 每个 NPC 随机 3 天赋，从 36 天赋池按 5 层权重抽取
3. 0.5% NPC 标记为天骄，强制优质天赋组合

#### NPC 三角金字塔

| 宗门层级 | NPC 范围 | 总人数（该层×宗门数） |
|---------|---------|---------------------|
| 顶尖大派 | 57~82 | 3 × ~70 = 210 |
| 一流门派 | 38~60 | 5 × ~49 = 245 |
| 二流门派 | 23~41 | 4 × ~32 = 128 |
| 旁门左道 | 10~26 | 5 × ~18 = 90 |
| **世界总计** | | **~500~800 NPC** |

各宗门固定 NPC（掌门+传功/护法，手动设计在 `npcStats.ts`）包含在此范围内，其余随机生成。

#### 天赋池设计（36 天赋 × 5 层权重）

| 等级 | 概率 | 数量 | 示例效果 |
|------|------|------|---------|
| 绝世 | 3% | 3 | 剑心通明（剑法×1.5）、龙脉觉醒（全属性+20%）、天生道体（修行×2.0） |
| 上等 | 11% | 6 | 战斗天才（攻+30%）、铁壁（防+40%）、疾风掠影（速+35%） |
| 中等 | 45% | 15 | 静心（修行×1.2）、铜皮铁骨（HP+20%）、精准（暴击+8%） |
| 下等 | 28% | 9 | 微弱势或无关紧要的标签 |
| 诅咒 | 11% | 3 | 负面：体弱多病、走火入魔、天生废柴 |

每个随机 NPC 抽取 3 次（无放回），权重按上述比例。

#### 天骄系统

- **比例**：0.5%（约 3~5 个天骄/全存档）
- **天赋保障**：强制至少 2 绝世 + 1 上等
- **额外加成**：修行速度 ×1.5、全属性（HP/MP/ATK/DEF/AGI/暴击）+20%
- **视觉标记**：NPC 名字金色、面板显示「🌟 天骄」标识

## 五、给新 AI 的开发指引

> 如果另一个 AI 接手开发，请遵循以下原则。

### 核心理念

1. **沙盒 = 游戏本体（地基）**：沙盒不是"可选的平行模式"，而是整个游戏的底层框架。剧情只是叠加在地基上的"作弊层"。

2. **在现有代码上叠加，不要重写**：
   - `skills.ts` 扩展字典，不要重命名已有 ID
   - `worldMap.ts` 在现有节点上新增，不要删除已有地点
   - `NPCGenerator.ts` 保留固定 NPC 逻辑，扩展随机生成
   - 所有新增 Zod Schema 字段必须带 `.default()`

3. **不要修改主线剧情代码**（`src/data/chapters/ch1.ts`~`ch3.ts`、`src/data/npcs.ts`）。黑月教是剧情专属势力，不要替换或删除。日月教是独立新增的沙盒势力。

4. **TypeScript strict mode**：所有新 ID 必须先在 `src/data/types.ts` 联合类型中声明，再在其他文件中使用。

### 类型修改步骤

```
1. src/data/types.ts → 在对应联合类型中添加新 ID
2. src/data/*.ts → 添加实际数据定义（skills.ts / worldMap.ts / talents.ts 等）
3. src/state/schemas.ts → 如果影响 PlayerState，同步更新 Zod Schema（带 .default()）
4. tsc --noEmit → 编译检查，确保无红色报错

```

### 方向 B：势力 AI 自主行动 ⭐⭐⭐⭐⭐

**当前痛点**：势力不会自己做决策。攻城是随机触发的，没有"AI 势力主动选择目标→集结兵力→发动攻击"的战略链条。玩家感受不到"群雄逐鹿"的动态。

**建议方案**：每月初执行 `factionAITick()`，每个 AI 势力走三步：
1. **评估自身**：检查 resources / stability / prosperity
2. **选择目标**：按（相邻 × 100 + 强弱比 × 50 + 正邪对立 × 20 + 城市繁荣度 × 0.5）评分相邻敌对城市
3. **执行决策**：攻城 / 整肃内部 / 征收资源 / 发展繁荣度

可新建 `src/systems/FactionAI.ts` 或在 `SectManagement.ts` 中扩展。

| 文件 | 改动 |
|------|------|
| `src/systems/FactionAI.ts` | **新建**：AI 月度决策引擎 |
| `src/screens/Camp.ts` | `advanceTurn()` 月初调用 `factionAITick()` |

**预估**：~300 行，中等复杂度。参考设计：三国志13 势力 AI（每回合评估→提案→执行）。

## 六、参考借鉴：龙胤立志传 vs DIY-dungeon 机制对照

### 门派资源与稳定度（参考太阁/三国志）

| 门派等级 | 初始资源 | 初始稳定度 | 代表 |
|---------|---------|----------|------|
| 至尊 | 500 | 70 | 武当、少林、日月 |
| 一流 | 350 | 60 | 峨眉、丐帮、全真、昆仑、唐门 |
| 二流 | 200 | 50 | 华山、崆峒、青城、点苍、铁掌 |
| 边缘 | 100 | 40 | 茅山、五毒、血刀、海沙 |
| 特殊 | 300 | 45 | 逍遥、魔教 |

- resources ≥ 500 → NPC 修炼效率 +20%；< 100 → -20%
- stability ≥ 70 → 防守战力 ×1.15；< 30 → NPC 10% 概率脱离
- 攻城消耗 -100 resources；胜方 +10 stability、败方 -15
